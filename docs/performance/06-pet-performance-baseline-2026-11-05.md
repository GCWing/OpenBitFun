# 桌面宠物性能基线报告

日期：2026-11-05。对象：当前默认 **BitBlob v2**。本报告不读取或修改真实用户的宠物选择；自定义宠物和其他预设的原生性能不由该样本代表。

## 结论

宠物独立 WebContent 的待机 CPU 中位数为 **1.94%**，工作态 **2.89%**；常驻 RSS 约 **196–202 MiB**。CPU 的 100% 表示一颗核心，不能将 2.89% 解读为整台 10 核机器的 2.89%。该窗口的运行时成本明显大于默认图片单份 RGBA 的理论大小 13.41 MiB。隐藏窗口保留这些内存；关闭/销毁窗口后，六次正式运行的宠物 WebContent 候选进程均退出。

不能由这些数据得出“宠物占用某个百分比 GPU”或“没有长期泄漏”。系统 GPU 指标包含其他应用，RSS 包含运行时和可共享页，WKWebView 没有向本次工具提供 JS heap。

## 方法与可复现身份

- Apple M5，10 逻辑核，16 GiB，Darwin 27.2.0；macOS 原生 WKWebView。Native 是 debug，前端是生产构建，不外推 release host 或 Windows/Linux。
- 本地基点 `18eeb95db0e7d49b068081b2120b1879f90e44ed`；工作区既有工作台/设计系统改动在前后构建中保留。本次基线以完成的 bundle 内容哈希为准。
- 优化前 `bundled-430fd6c0fc1530b6`；优化后 `bundled-ce86dd79f9268b72`。
- 六次使用同一个 native binary：SHA-256 `04bc43523a1ddee4e10861262bfeadaa4435d4e5b63f60e1735d9b3be50cbce2`。测量 harness SHA、完整协议和每次环境保存在证据 JSON。
- 三组顺序 **AB / BA / AB**。每次独立进程、应用数据和 WebView 存储；不使用真实账号、模型、会话或工作区。
- Shell ready 后等待 15 秒。每个阶段先隐藏主窗口，再稳定 5 秒，测量 20 秒；两端断言主窗口仍隐藏。共 30 个资源窗口，约 600 秒正式资源采样。本任务没有在采样期间并发启动构建或测试；其他桌面活动无法完全隔离。
- 顺序：宠物销毁后的控制段 → 新建宠物待机 → 工作＋固定任务气泡 → 隐藏但不销毁 → 关闭并销毁。工作气泡由真实 companion event contract 注入 fixture，不代表真实 Agent 流式执行。
- 每秒读取 `ps` 累计 CPU 时间 / RSS 和 `ioreg AGXAccelerator`。CPU = 进程累计 CPU 毫秒差 / 实际墙钟毫秒差 × 100；20 秒窗口的 10ms CPU 时间粒度约对应 0.05 个百分点。
- 原生宿主 PID 已知；WebKit 是启动期间新增的候选 PID。重新创建宠物窗口时新增的 WebContent 标为宠物候选，随后冻结 PID 集。该识别比全系统进程求和更窄，但不是操作系统提供的所有权证明。
- RAF/精灵帧探针在资源窗口外单独执行，每次 2.6 秒。它观察调度和 computed style，不证明每帧合成像素或 GPU 完成时间。没有使用 computer use 或浏览器控制工具。

原生鼠标没有被测试控制。第二组基线待机段开始时仍在注视，之后恢复走帧；该次数据保留并在优化报告单列，不能将三组当作严格相同的静止输入。正式结果之外的早期主窗口显示污染、守卫失败和调度实验均保留在证据 JSON 的 `excludedDiagnostics`，不混入下表。

## 图片与缓存分析

默认 BitBlob：1536×2288，8×11 单元，单帧 192×208；WebP **1,523,708 bytes（1.45 MiB）**，若完整解码成单份 RGBA8 则为 **13.41 MiB**。这个乘法估算不是实测 GPU 分配。全部内置预设的尺寸与编码体积见证据 `atlasInventory`（共 14 个，包含 BitBlob）。v1 通常为 1536×1872，单份 RGBA8 为 10.97 MiB。

桌面显示为 96×104 CSS 像素，在 2× 像素密度下与原单帧像素数一致。直接减半图片会牺牲这类显示器的清晰度，改换编码也不会自动减少相同解码尺寸的内存。本轮保留原始图片。

用户宠物由 host 读取为 Buffer，再生成缓存 Blob URL；这是独立于内置路径的内存风险。原实现只有完成缓存，没有并发中的去重：同时请求可生成多个 URL，Map 只保留最后一个，早先 URL 无法通过删除入口回收。删除期间仍在加载的请求还能重新填入缓存。这两个竞态已在优化版修复并通过聚焦测试。默认 BitBlob 不走这条 Blob 路径，因此不能用默认宠物 RSS 来证明该修复节省了多少内存。
