# 性能优化收尾报告

日期：2026-11-06。范围：工作台页面、首页与隐藏页面、长驻留、生成中并发、终端、Browser、MiniApp、桌宠及E2E测量。按用户要求结束本轮工作，文件编辑器专项已停止；没有继续分析或调整Monaco生命周期。

## 整体结论

已解决几项可复现的主要开销：分栏拖动中的广泛样式／布局工作、本地MiniApp列表等待市场网络、首页动画的持续渲染成本、取消输出后的滚动空转，以及隐藏终端的无效重绘。同时修复了logo错位、终端尺寸不同步和PTY自然退出未回收等功能问题。

**成果是多个具体场景的改善，不是“全应用性能目标全部完成”。** 普通导航和基础拖拽在对应短流程中通过门槛；更长驻留、生成工具启动、终端个别切换和Browser展示仍有超标。未证明整体常驻内存、应用级GPU利用率或显存全面下降，也没有完成release、其他OS和真实远程验收。

不同阶段的字体、输入协议、工作量和原生程序有调整，下列结果分别在各自匹配对照内成立，不能相加或折算成一个“整体提升百分比”。本报告记录性能优化收尾时的工作区状态。

## 已取得的主要结果

| 场景 | 实测前→后 | 结论与边界 |
| --- | --- | --- |
| MiniApp本地库热切换 | 内容P95 2593→65 ms | 解除本地展示对市场请求的等待；市场刷新、loading/error保留。第一轮实测为空本地库，不代表应用运行态或市场服务加速 |
| 左侧导航分栏拖动 | 每次帧间隔P95 64–66→23–25 ms；最大137→67 ms | 从明显卡顿降到本轮<34／<100 ms门槛内；实际位移与归位通过 |
| 中间内容分栏拖动 | P95 70–73→19–21 ms；最大152→59 ms | 同上；没有通过降低输入采样或丢弃阅读位置获得收益。<1%慢帧进阶目标未全部达到 |
| 首页可见时持续CPU | 主WebContent 19.27%→0.90%；宿主9.88%→3.56%；GPU进程CPU 4.53%→0.30% | 三对旧`harmony-bundled`配置下的结果，主CPU约−95.3%；不能直接宣称macOS默认字体也降低相同比例。实际Apple配置后来另测首页主CPU约0.93%，这是基线观察，不是前后收益 |
| 取消生成后的空转 | 主CPU 4.39%→0.93%；唤醒44.59→7.03次/秒；宿主4.62%→2.76%；GPU进程CPU 0.64%→0.37% | 三对同协议结果，主CPU约−78.8%；滚动量化导致的持续RAF循环已消除。工具启动等其他阶段仍有长帧，不能将此收益推广到所有生成场景 |
| 三终端全部隐藏且持续输出 | 主CPU 25.27%→9.61%；GPU进程CPU 2.13%→0.67%；可归属进程CPU合计44.38%→31.21% | 三对均支持隐藏重绘下降，合计约−30%；但宿主14.21%→17.83%，一次热反馈106 ms超门槛，整体仍未验收 |
| 桌宠 | 待机CPU 1.94%→1.79%；工作态2.89%→2.74% | 六次隔离运行的小幅观察，输入有干扰，不能承诺稳定百分比；默认宠物内存基本持平 |
| E2E原生求值桥接 | 两组400次调用：250.8／364.4→138.9／150.7 ms；主CPU 168.3／216.6→27.3／52.5 ms | 固定包装源码、数据走原生参数接口；只算测量工具开销改善。按收尾要求第三组未启动，保留为两组pilot，不算产品页面收益或完整三组验收 |

CPU百分比的100%表示一个逻辑核。GPU进程CPU表示该进程消耗的CPU时间，**不是GPU硬件利用率**。帧间隔来自RAF，输入到RAF不等于系统可信输入到最终像素的延迟。

## 实际完成的修改

- **页面与布局：** 本地MiniApp数据独立展示；缩小拖拽尺寸变量的样式传播范围；隐藏页面跳过无意义的布局／绘制，保留状态和订阅；待办展示时钟随可见性休眠，返回时立即校时。
- **首页与logo：** 将运动部件放到SVG外的HTML合成图层，原SVG承担布局占位，按原viewBox映射坐标并响应尺寸变化。早期造成错位的方案撤回；保留方案验证位置、尺寸、滚动与原动画节奏。
- **流式会话：** 状态槽退出动画结束后停止隐藏旋转；修复滚动缓动遇到原生坐标量化无法收敛的问题，保留原目标、缓动、用户阅读接管和增量展示。
- **终端：** 修复连续拖拽／恢复竞态造成PTY尺寸漏同步；增加真实子进程等待与退出发布，回收自然退出的shell并保留末尾输出；回补隐藏xterm选区刷新绕过绘制暂停的路径。后台PTY继续运行，未缩短scrollback或改变标签detach语义。
- **页面生命周期：** 修复标签栏嵌套坐标、快速切换露出目标和手动滚动取消；补齐场景准备阶段在卸载／Suspense路径的清理。这些是功能与生命周期修复，不分别编造性能收益。
- **桌宠：** 修复注视后的动画恢复、无效计时器及隐藏鼠标轮询；合并用户精灵图并发加载，防止释放过程中的旧请求回填和孤儿Blob URL；保留图像分辨率与可见动画。
- **自动化驱动：** 修复iframe选择后的内部桥接引用；仅释放已失效的跨文档元素句柄；macOS脚本通过原生字典传参，保持每次重新求值用户表达式及原有错误／超时／frame语义。

没有扩大“首次点击才加载”的范围，也没有通过切页卸载业务状态、停止正常数据刷新或取消可见动画降低数字。当前证据支持保留既有懒加载与空闲预热；尚无同条件release冷启动／关闭预热A/B，不能声称懒加载已节省某个具体MB数。

## 测量与验证成果

建立了可复用的原生E2E流程：隔离工作区／用户数据，冻结前端与native快照，校验协议、脚本、字体与构建hash，分开报告功能通过和性能预算通过，交替运行A/B并保留全部原始样本。构建、截图和原生分配检查与计时窗口分离。

后续测量使用Darwin进程归属及PID启动时间，分别观察主WebContent、桌宠、宿主、GPU进程；以窗口外CPU脉冲识别WebView归属。校正了字体配置、pointerdown计时、焦点／可见性、旧iframe句柄保留及脚本桥接自身开销。诊断插桩不当作正常产品验收；原生分配读取、RSS、physical footprint、JS堆和显存明确区分。

代表性已完成证据：

- P0三对：6次完整运行、444次打开／切换、48次计时拖拽、18个资源窗口、48张头像截图；对应功能与速度预算通过。截图裁剪前后0差异，四条1600 ms动画及六类首页刷新请求保持。
- Apple默认配置长驻留：28.74分钟、480次导航，功能通过，尾延迟预算未全部通过；随后补充真实pointerdown路径及无编辑器协议。
- 生成中并发：600段有界输出、4次真实命令、4次真实文件编辑，同时输入／阅读／切页／拖分栏；另有120段取消。多轮三对比较已完成，功能与速度／资源结果分别记录。
- 终端：三PTY各12万行，三对比较均完成；真实TTY尺寸、输入回应、隐藏输出、同PID恢复、自然退出、末尾内容与进程回收有断言。
- Browser：三个原生子WebView，页面切换、输入、滚动、Canvas／Worker、隐藏恢复、关闭；两项候选分别完成三对，另有16组截图／预览解码像素一致性检查。
- MiniApp：30条本地安装记录、3个真实应用与Worker，首开、热切换、输入／计算、隐藏业务推进、恢复和逐个关闭；完成基线，尚无产品优化A/B。
- 最新驱动修改：新旧原生脚本语义／嵌套iframe回归通过，候选真实Browser多会话9项检查通过；资源对照最终完成2组、4次运行、16个窗口条件检查。

各模块的聚焦测试、类型检查及构建按阶段执行，详细日志见原报告；不把跨快照的检查相加成“最终整包全量通过”。本次收尾不再开启新的原生页面验证。

## 尚未完成的目标

- **速度：** 新pointerdown基线的首页／会话反馈P95仍为113／136 ms；会话内容152 ms略超150 ms。生成工具启动仍有>100 ms长帧；Browser原生展示、终端个别热反馈及MiniApp拖拽P95 36 ms未达目标。连续交互慢帧<1%的进阶目标未全面完成。
- **资源：** MiniApp全部隐藏时主CPU约18.56%、GPU进程CPU约12.70%；关闭后主footprint仍约增加43–45 MiB。会话关闭约230秒后主footprint仍约481 MiB，已观察根节点回收且逻辑缓存约3.08 MiB，但分配器碎片、代码资源及实际对象保留链尚未完全分离。不能把残留footprint直接称为泄漏或已解决。
- **GPU与内存证据：** 未取得应用级GPU busy／独占显存和完整JS对象保留链。系统AGX计数、GPU进程CPU及RSS／footprint不替代这些指标；没有可信的全应用“节省内存总量”。
- **首开与规模：** release冷启动、加载／预热策略A/B、大工作区搜索／Git／watch、大量列表、中文IME／大段粘贴、多个会话同时生成及更长时间压力仍缺同口径结果。
- **平台与远程：** 本轮为本机macOS/WKWebView、debug host＋生产前端；Windows、Linux、真实SSH／Docker工作区、Remote Control、Peer Device、Detached Dispatch均未实际验证。

后续若恢复性能工作，应从这些明确缺口选择范围，并固定经过校正的测量协议重新建立对应基线；本轮不再自动继续。
