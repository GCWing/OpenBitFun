# 后台任务的结果投递

[English](background-result-delivery.md)

一次后台运行需要分别回答三个问题：任务执行得怎样、结果是否需要报告、保存的记录是否读取成功。任务执行成功可以无需汇报；记录读取失败也不能据此断言任务执行失败。

## 投递规则

| 设置 | 含义 |
| --- | --- |
| 按任务说明 | 沿用任务内容里的报告要求；只有明确允许不报告时才能静默。旧任务默认使用此设置。 |
| 每次报告 | 每次结果都投递，模型不能用“保持静默”覆盖此设置。 |
| 符合条件才报告 | 按任务内容里写明的条件决定是否汇报。 |
| 无法识别的设置 | 保留原值和运行记录，显示结果。 |

运行所属主机记录 `pending / quiet / report / attention` 四种投递状态：尚未判定、无需汇报、需要报告、需要关注。判定绑定任务 ID、运行 ID 和执行代次，先保存，再发送完成事件。执行失败或中断优先于模型的静默提议；判定不明确、判定服务不可用或判定保存失败时，继续显示结果。

普通对话不能通过复制元数据获得后台运行的权限。当前接入的是原生定时任务调度器；判定逻辑不依赖某条任务的名字、日志、语言或固定措辞。其他后台生产者需要接入相同的运行身份和消费合同，不能直接复用一个未经验证的静默标记。

## 兼容模型输出

模型可以用 `Cron action=report` 提交结构化投递提议。这个操作只记录当前运行的提议，不重新执行任务，也不结束任务。明确提交静默提议后，模型正常返回空内容也可以完成；思考未完成、流中断、需要回答的问题、权限确认和 Stop hook 仍使用现有处理机制。

模型仍然回复“保持静默”的说明时，主机通过配置的 `fast` 模型进行一次无工具的兼容判定。输入包含本次保存的任务要求、当前运行中可用的模型和工具文本、最终输出、结构化提议，以及可用的上一轮输出。模型输出是待判断的证据，不能成为判定器的新指令。

只有明确授权静默、明确没有满足报告条件，并返回有效结构化结论时，才收起报告。信息不足、矛盾、异常工具调用、格式错误、超时等情况均显示结果。这里采用语义判定，没有针对“保持静默”或某条任务的关键词屏蔽。它判断报告意图，不能代替对任务事实的独立核验。

兼容判定最多等待 30 秒，输入预算为 64 KiB。这是投递阶段的 IO 预算，不限制 Agent 执行循环。额外用量单独记入 `decisionUsage`，可在静默运行的展开记录中查看；原任务的输出和用量记录保持原义。

## 展示和未读

- 无需报告的运行显示为可展开的执行记录，默认收起模型的静默说明和工具内容。展开后仍可查看原任务和原始输出；搜索命中时会展开。
- 失败、未知版本、待回答问题和待确认权限保持可见。
- 静默运行不产生新未读，也不清除先前未读或待关注状态。
- 最近一次执行与未读结果分别保存。例如 11 点静默执行完成后，9 点尚未读的结果仍指向 9 点；读取它也不能清除后来 13 点的新结果。
- 恢复执行使用新的代次。旧的静默决定不能遮住恢复结果；恢复完成作为执行状态的变化需要报告，旧决定保留在审计历史里。

桌面通知消费同一个投递结论，并同时订阅完成和独立失败事件。同一次终止结果的重复事件会合并。窗口焦点、通知设置及子会话规则仍然有效。微信主动投递在记录保存完成后读取判定，静默说明不发送，后台执行错误保持可见；用户主动发起的 bot 对话继续使用原回复路径。

## 记录读取失败后的恢复

历史边界提示改为“记录读取失败”，不再用“暂未准备好”暗示模型还在生成内容。

“重新同步记录”会从会话所属主机读取新快照，再判断边界之外是否还有记录。它不会重跑定时任务，也不会发送新的 Agent 请求。如果所属主机确认已经到达最新边界，就清除残留错误。

异步读取同时校验设备、会话、展示代次和请求票据。旧请求不能覆盖新的同步结果，保存的快照不能缩短正在显示的流式输出，视口更新继续由现有分页提交和锚点机制负责。失败原因和目标序号会进入日志，重复的同类失败会合并记录。

Detached Dispatch 的记录由目标主机的事件重放负责，控制端不提供本地快照同步入口，避免误读控制端文件。本次没有为 detached job 或其他后台生产者增加静默投递策略。

## 分层和兼容

DTO 位于 `core-types`，纯判定位于 `agent-runtime::scheduler::result_delivery`；Core 负责运行接入、模型服务、持久化和事件接线；Services 投影保存的事实；Web UI、手机和 bot 负责各自展示。判定发生在执行所属主机，不依赖控制端保持连接。

旧任务、旧事件和旧未读数据均有默认读取路径。未知策略字符串保留，未知投递版本保持可见，不删除或重置用户记录。较早的观察端保存不能把已确定的投递结论改回待判定，也不能丢掉旧代次的审计记录。

Peer Host 和 Remote Connect 声明 `background_result_delivery_v1` 能力。对端不支持时，编辑器禁用新策略设置，其他字段继续沿用旧路径；API 在发送新策略字段前检查能力。旧客户端仍能收到原始运行内容。

## 验证边界

已覆盖纯判定、磁盘完成与检查点、恢复代次、旧格式往返、未读收据、通知、远端记录投影、Peer 能力及旧主机拒绝，以及真实 Chrome 中三种屏宽下的手机展示。Host Stream 浏览器测试使用模拟主机和 relay。

真实 SSH / Docker、第二台设备、真实 IM 投递和配置模型的语义判定准确率尚未实测；本地和合同测试不能证明这些场景已经端到端通过。各模块的针对性验证命令见所属 `AGENTS.md`。
