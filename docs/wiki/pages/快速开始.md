# 快速开始与数据迁移

## 安装

从[官方下载页](https://openbitfun.com/download)获取 Windows、macOS 或 Linux 安装包，核对系统和架构；签名检查见[下载验证](https://github.com/GCWing/OpenBitFun/blob/v1.0.0/docs/verify-downloads.md)。Nightly 是独立的可能不稳定的构建渠道。

## 从旧 0.2.x 版本迁移

OpenBitFun 1.0 与旧 0.2.x 安装的数据不兼容，不要直接指向旧数据目录并假设普通升级会自动转换全部内容。

可选的[数据迁移工具](https://github.com/GCWing/OpenBitFun/blob/v1.0.0/src/apps/data-migrator/README.zh-CN.md)支持旧稳定版 0.2.17–0.2.19。更早版本需先升级旧应用，并确认旧数据仍可正常读取。

1. 备份数据，关闭两款应用、CLI 实例及后台数据写入进程。
2. 在拥有数据的机器上打开迁移工具。
3. 核对源与目标目录，选择数据组，扫描并审阅预检计划。
4. 执行迁移，检查警告、跳过项、冲突和报告。
5. 自行打开 OpenBitFun，按报告修复路径或重新登录。

迁移工具不会自动删除源数据。不要把删除或重置任一应用数据当作通用修复方式。迁移远程连接记录不等于迁移远程机器。

## 开始第一项任务

1. 按初始化流程配置受支持模型服务或自定义地址，核对凭据、模型能力并测试连接。“配置已保存”不代表“连接成功”。
2. 打开包含代码、笔记、数据或其他材料的项目目录。
3. 新建会话：小任务可从 Minimal 开始，多步骤工作可选 Standard。
4. 初次使用选择需要审批的权限方式。
5. 说明目标和限制，并检查实际结果。

适合首次使用的提示：

- “解释这个项目，不要修改文件。”
- “把这些笔记整理成简报，指出没有依据的说法。”
- “分析这份表格并保存报告；修改原始材料前先询问。”
- “规划一个小改进，实施前等我确认。”

模型服务可能产生费用。核心本地工作不要求账号登录；账号设备控制和 Pages 需要相应账号服务。
