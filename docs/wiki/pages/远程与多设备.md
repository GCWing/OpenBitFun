# 远程与多设备

## 先分清远程场景

| 场景 | 连接的是什么 | 执行与数据归属 |
| --- | --- | --- |
| 远程工作区 | 工作区 IO 与命令指向 SSH/容器/WSL | Agent Runtime 和会话元数据仍在 OpenBitFun 宿主，文件和工作区命令使用目标环境 |
| 远程控制 | 手机或 Bot 向宿主发送请求 | 已连接宿主拥有执行和会话 |
| Peer Device Mode | 本地界面使用另一设备的产品命令/事件 | 所选 Desktop/CLI 拥有工作和记录 |
| Detached Dispatch | 向另一主机提交持久任务 | 目标拥有运行时、任务会话、托管 worktree 与记录 |

它们不是可以互换的“远程模式”。远程工作区不会自动在目标安装或启动 OpenBitFun。前提条件见[Peer Device Mode](Peer-Device-Mode-中文)与[Detached Dispatch](远程任务派发)。

## 手机与 Bot 控制

1. 在宿主打开 Remote Connect。
2. 选择局域网或配置好的官方 Relay 路径，检查连接状态和网络信息。
3. 宿主和手机控制端使用相同 GitHub 身份登录，再按二维码邀请流程连接。二维码包含端点/设备身份，不是匿名访问授权。
4. 确认宿主与工作区，再发送请求或查看已有会话。
5. 在驱动端回答支持的权限请求，断线后重连恢复历史。

当前界面没有独立 ngrok 或 custom-server 页签。同网络模式在宿主启动 Relay，局域网和官方 Relay 都通过 GitHub 身份验证，登录需要互联网。官方端点固定；自托管需匹配的客户端构建，不是填写服务器 URL 或使用部署向导。参阅[Relay 指南](https://github.com/GCWing/OpenBitFun/blob/v1.0.0/src/apps/relay-server/README.md)。

飞书、Telegram、微信/iLink 有专门 Bot 配置。会话控制范围随表面与连接器不同；移动网页支持自适应布局，但不代表全部桌面能力等价，也不意味着手机拥有独立任务运行时。

## 远程工作区

目标包括 SSH、跳板机链、SSH 主机上的 Docker、本地 Docker、容器 sshd，以及执行 Windows 宿主上的 WSL。配置并测试连接，选择真实目标工作区路径，确认终端和文件属于目标环境。

远程路径使用 POSIX 分隔符。容器路径位于容器内部，主机挂载只按挂载位置可见；Docker 命令需要兼容的 POSIX shell。

智能体 Grep/Glob 与远程文件名搜索可通过支持的 Provider 使用。远程 Flashgrep 加速内容搜索和索引入口不可用，应用不应悄悄搜索本地文件；远程文件回滚也有覆盖限制，见[编程工作台](编程工作台)。

Git 提示目录所有权不安全时，核对目标，在仓库所属机器自行授予 safe.directory 信任；OpenBitFun 不会静默授予远程信任。

## 断线与安全

控制端断开不等于取消任务。执行宿主仍需保持运行，等待权限的任务仍需有人回答。配对内容加密不隐藏全部路由元数据，也不能保护已被攻破的端点，见[安全说明](安全与隐私)。
