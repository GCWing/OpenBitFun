# 编程工作台

## 从需求到可检查的改动

1. 打开正确项目，核对它属于本地、SSH、容器、WSL 还是另一台设备。
2. 请智能体检查相关代码并解释发现；只需规划时，明确禁止修改。
3. 审阅方案后，授权在约定范围内实施。
4. 运行项目检查，查看差异及未解决的失败。
5. 提交、推送或发布前审查改动。

执行方式见[Harness 选择](Agent-模式)。调试、规划、调研和审查不需要按旧指南寻找同名模式按钮。

## 集成工具

- 文件与编辑器：浏览和整理材料、搜索、编辑代码/文本、查看 Markdown/图片与差异，使用可用的语言服务和内联 AI。
- 终端：执行命令，使用多个终端视图，检查后台进程。
- Git：查看改动、历史、分支和 worktree；在获得相应授权后暂存、提交、推送或拉取。
- 浏览器：检查页面、完成受支持交互并收集可视化证据。
- 审查：请求可操作的问题，或使用现有评审流程；只读审查不应悄悄实施修复。
- 会话：分开保存不同对话，查看修改文件并管理历史，见[会话管理](会话与持续目标)。

语言服务、浏览器与电脑操作依赖服务配置和系统权限。命令成功不等于生成的应用已正常工作。

## 恢复不等于完整备份

分叉会话复制的是对话历史，不是独立文件系统。快照与回滚取决于已记录覆盖和目标支持，不能保护所有命令和外部副作用。

远程会话目前不能在覆盖未确认时执行完整文件回滚或编辑后重跑；部分已记录操作仍可在断线后展示差异。使用 Git 提交与备份保障恢复，不要假设会话分叉能隔离工作。
