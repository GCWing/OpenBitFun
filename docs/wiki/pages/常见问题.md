# 常见问题

## OpenBitFun 只适合编程吗？

不是。编程、调研、办公与创作共享 Agent 工作空间，制作文档和分析数据不要求单独 Cowork 模式。

## 应该选哪个模式？

通用 Harness 是 Minimal、Standard、Ultimate、Creative。小任务从 Minimal 开始；日常多步骤任务选 Standard；复杂工作选 Ultimate；创建/定制工作空间可选 Creative。见[选择说明](Agent-模式)。

## 能先规划而不实施吗？

可以，明确说“先调查并给方案，不要修改”。Harness 不会覆盖任务范围或权限规则。

## 可以在会话中途切换 Harness 吗？

当前选择器在首轮前选择；会话开始后改选其他执行配置会要求新建会话。见[会话管理](会话与持续目标)。

## 能直接从 0.2.x 升级吗？

旧数据与 1.0 不直接兼容。使用支持稳定版 0.2.17–0.2.19 的可选迁移工具，并保留备份。见[迁移步骤](快速开始)。

## 免费吗，需要账号吗？

核心代码采用 [MIT 许可](https://github.com/GCWing/OpenBitFun/blob/v1.0.0/LICENSE)。模型 API、云语音、基础设施及其他服务可能收费。核心本地使用不要求 OpenBitFun 账号；账号设备控制与 Pages 依赖相应账号服务。

## 可以离线使用吗？

取决于模型、语音、工具和依赖是否能离线运行。云端地址和联网调研自然需要网络。

## 能生成可编辑办公文件吗？

受支持 Skills/工具链可以生成可编辑成果。确认依赖并检查保存结果，不是任意模型自动支持全部格式。

## 会上传整个项目吗？

核心使用不要求把整个项目上传到账号，相关内容仍可能发送至模型或外部工具。见[隐私说明](安全与隐私)。

## SSH、设备控制与派发有什么区别？

SSH 改变工作区 IO/命令目标，Agent Runtime 仍在宿主；设备控制使用另一宿主的状态与执行；派发提交目标拥有的持久任务与托管 Git worktree。见[远程对照](远程与多设备)。

## 控制端可以关闭吗？

已接受的设备任务属于执行运行时，而非控制端界面。Dispatch 在持久接受后可随控制端断开继续；执行宿主和依赖仍需可用，权限等待仍可能阻塞。

## 分叉会话会隔离文件吗？

不会。它复制历史并保留工作区绑定，远程分叉共享工作树。文件隔离请使用 worktree 或独立工作区。

## 可以用手机或消息平台吗？

可以，通过受支持 Remote Connect 手机/Bot 流程。浏览器/设备控制两端使用相同 GitHub 身份，局域网也如此；二维码邀请不是匿名授权。Bot 按连接器配置凭据。各表面能力不同，见[远程控制](远程与多设备)。

## 语音输入和实时通话相同吗？

不同。听写先生成可编辑文字再发送；实时通话持续语音协作并可请求项目工作，有独立服务要求。见[语音](语音与实时通话)。

## Mini Apps、Pages、皮肤有什么区别？

Mini Apps 是已安装交互工具；Pages 发布版本化静态成果；皮肤改变外观。见[Mini Apps 与 Pages](Mini-Apps-与-Pages)和[定制](自定义与扩展)。

## 可以使用其他生态的全部插件吗？

兼容是选择性的。发现、导入、启用不同；OpenCode 静态预览不代表完整实时插件执行。见[兼容限制](自定义与扩展)。

## 去哪里获取帮助？

[Playbook](https://playbook.openbitfun.com)、[Issues](https://github.com/GCWing/OpenBitFun/issues)与[贡献指南](https://github.com/GCWing/OpenBitFun/blob/v1.0.0/CONTRIBUTING_CN.md)。附版本、系统、目标、错误文本和复现步骤，移除密钥；安全问题私下报告。
