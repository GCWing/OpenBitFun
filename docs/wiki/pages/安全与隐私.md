# 安全与隐私

## 数据流向取决于工作流程

核心本地工作不要求把整个项目上传到 OpenBitFun 账号，但相关提示、文件、图片和工具上下文仍可能发送到配置的模型或外部服务。云端语音、MCP、消息平台、市场服务和 Pages 各有数据边界。

“本地优先”不代表全部处理都在本地。SSH 工作区的运行时/会话元数据保留在宿主，工作区 IO 指向目标；Peer Device Mode 与 Dispatch 则由其他宿主执行。

## 权限与重要操作

不熟悉的工作采用需要审批的权限方式。Full Access 减少询问，不是沙箱，也不保证操作无害。记住的规则是真实授权，应保持范围狭窄。

批准文件修改、命令、浏览器/电脑操作或扩展前，检查目标、可逆性、凭据和泄露风险。麦克风、屏幕录制与输入控制等系统权限另行管理。

调研或起草请求不等于购买、发消息、发布或删除的许可。备份重要数据，会话回滚不能撤销全部外部影响。

## 远程流量与端点

配对内容端到端加密，但路由、时间、在线状态等元数据不一定隐藏。模型服务流量、Bot 平台、已发布 Pages 与被攻破的设备，不会因为 Relay 加密就自动获得相同保护。

确认执行设备与服务部署可信，撤销不再使用的设备/连接。公共 Relay 不意味着可用性、合规或保留策略保证。

## 扩展

- Skills 提供指令，仍需检查代码和依赖要求。
- MCP 暴露外部工具，应限制服务和权限。
- Mini Apps 请求路径/工作区访问，可能使用 Worker 和模型。
- Hooks 执行命令；项目 Hook 默认关闭，需审阅。
- 生态发现不等于批准所有导入代码执行。
- ACP 进程具有独立的权限与信任假设。

更新时检查新增权限。导入无法解析时保留副本与来源配置，不要通过重置用户数据恢复。

## 账号、发布、记忆与语音

Pages 发布是有意披露，检查可见性和最终分享链接。账号设备控制依赖配置的服务。记忆、会话洞察与语音设置需分别审查。本地和云端转写数据流不同，实时语音也取决于所配置服务。

旧数据采用[迁移流程](快速开始)，在数据所属机器执行并检查警告，不要删除旧记录。

## 私下报告漏洞

遵循[安全政策](https://github.com/GCWing/OpenBitFun/blob/v1.0.0/SECURITY.md)，使用[私密漏洞报告](https://github.com/GCWing/OpenBitFun/security/advisories/new)，不要在公开 Issue 中发布利用细节、密钥或个人记录。
