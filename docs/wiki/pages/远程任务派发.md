# Detached Dispatch 远程任务派发

## 提交目标主机拥有的任务

派发将持久工作提交到另一台 OpenBitFun 主机。目标持久接受后，控制端可以断开；目标拥有 Worker、会话、worktree、执行记录与权限邮箱。

## 准备与提交

1. 打开 Git 仓库或托管 worktree。派发工作区交付仅支持 Git，不是任意目录上传。
2. 打开会话派发选择器，选择受支持 SSH 或账号设备目标。
3. 核对协议/能力、目标 CLI/运行时、模型配置和权限，审查准备过程要求的安装/更新或模型同步。
4. 选择基线版本，决定是否包含未提交的 Git 可见改动。
5. 审查任务并提交，断开前等待目标持久接受。
6. 跟踪任务状态，重连后恢复执行记录。

目标获得托管任务 worktree，不是调用者随意指定的执行目录。选择包含未提交改动时，它们在控制端托管基线 worktree 中提交，不会暂存或切换用户原检出。被 Git 忽略的 .env、构建产物等不交付，目标所需依赖要另行准备。

## 查看、回答与取消

检查状态、错误和权限等待，远程回答支持的请求，或明确取消目标任务。执行主机需保持可用，控制端断线不能让已关机目标继续运行。

提交结果不确定时先查看已有任务记录，再决定是否新建，不要因为失败或离线就删除可恢复记录。

## 有意同步结果

控制端基线和目标 worktree 不是实时共享目录，原检出后续改动不会自动传给运行中的任务。结果同步把目标任务分支导入控制端托管基线，检查改动后再整合到正常分支。

同步可能提交目标任务 worktree 中 Git 可见改动，是有意变更，不是只读刷新。
