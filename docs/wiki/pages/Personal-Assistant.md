# Personal assistants

Personal assistants keep dedicated identity and context for recurring responsibilities. They are not an extra general Harness and do not require separating ordinary work into Code and Cowork.

## Create and configure

1. Open Assistants and create or choose an assistant.
2. Define its name, role, avatar, and working style.
3. Review identity/persona files: IDENTITY.md, SOUL.md, and USER.md.
4. Configure the applicable Skills, built-in tools, MCP services, and model.
5. Start a conversation from the assistant card or detail page.

The defaults configuration for new assistants controls their starting capabilities. Inspect enabled, unavailable, shadowed, or changed items; do not assume changing defaults rewrites every existing assistant.

## Ongoing work

An assistant has its own workspace and sessions. Use [scheduled tasks](Tasks-and-Automation) for recurring work, and check that the execution host and required services remain available. A personality file alone does not create a background job.

## Memory and insights

Long-term memory can retain durable preferences and knowledge from sessions, subject to memory configuration. Inspect and manage it separately from the assistant's identity. Clearing memory is not the same as deleting session history.

Session insights summarize activity across a chosen period. Treat them as reflective reports and verify important conclusions against the underlying work.

Voice input, realtime calls, and optional desktop companions are separate capabilities; see [voice](Voice-and-Realtime). Resetting a workspace or deleting an assistant is an explicit data operation: back up anything you need first.
