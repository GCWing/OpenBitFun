# 自定义与扩展

## 从最小扩展开始

1. 调整角色指令与权限。
2. 用 Skill 封装可重复知识。
3. 通过 MCP 连接外部工具。
4. 用 Mini App 提供专用界面。
5. 用可信 Hook 控制生命周期行为。
6. 按需使用选择性生态兼容或 ACP。
7. 产品本身确需改变时再修改源码。

## 智能体、Skills 与 MCP

在智能体管理中检查内置、用户、项目和外部角色。根据当前宿主目录配置工具/工具组、Skills/Skill 组、模型策略与只读限制。子智能体处理边界明确的委派任务，不代表每个角色都是通用 Harness。

Skills 提供流程指引，可能依赖运行环境；注意来源、范围、遮蔽与可用状态。MCP 需要配置传输和认证、测试连接，再为相关智能体明确选择服务/工具。MCP 配置已保存和服务已连接是不同状态。

## Hooks

OpenBitFun 原生用户 Hook 实现 Codex Hook 契约，并记录具体差异。使用 OpenBitFun 自己的用户/项目配置文件与“设置 → Agent Hooks”。项目 Hook 默认关闭，会执行仓库代码，审阅后再开启。

兼容的 Claude Code/Codex 命令 Hook 可作为显式审查的快照导入；更新需再次审查，删除托管副本不会修改来源工具文件。Hook 管理与执行为本地能力，远程工作区会返回不支持。

OpenCode 插件回调仅供发现/静态预览，不是可执行原生 Hook。路径、开关与限制见[OpenBitFun Hook 指南](https://github.com/GCWing/OpenBitFun/blob/v1.0.0/docs/features/agent-hooks.md)。

## 生态兼容

兼容界面覆盖 OpenCode、Claude Code、Codex、DeepSeek Harness 与 PI，请逐来源、逐类别查看状态。发现、导入副本、启用、连接依赖是不同步骤。

选择受支持的 Skill/MCP/Hook，审查导入计划与冲突后确认副本；Command、Tool、子智能体使用各自受支持路径，不是通用插件执行。DeepSeek Harness/PI Hook 目录为只读，OpenCode 托管包/静态预览不能描述为完整实时运行时。

## 皮肤与客户端定制

在“设置 → 应用 → 外观”选择主题、语言、字体、本地外观包和 Skin 市场。应用前预览，保留可恢复的内置外观，检查市场更新。[Skin 市场](https://market.openbitfun.com/skin/)。

Creative 提供客户端界面/运行时定制，与视觉皮肤和修改构建源码产品不同。源码开发遵循[贡献指南](https://github.com/GCWing/OpenBitFun/blob/v1.0.0/CONTRIBUTING_CN.md)。ACP 连接受支持的外部智能体进程，仍有独立配置与信任边界。
